## R2-01 / P1：并发会话的运行状态相互污染

**复现**

1. session-005 发送纯文字长请求：列出 500 项测试点，不使用工具。
2. A 仍运行时新建 session-006，发送短请求“只回复 QA-B-OK”。
3. 留在 B，等待短回复完成。

**实际**：B 显示 `QA-B-OK` 和“执行完成”，但输入框不可用，仍显示“停止”、模型思考/生成状态，重新生成按钮也禁用。

**证据**：同一时刻磁盘中 session-005 的运行状态为 `running`，session-006 为 `completed`。B 的运行在时间戳 1788603541884 已结束。随后切回 A 点击停止，未删除任一会话。

**原因**：`web/src/App.tsx:312` 的 `pendingStreamsRef` 是全 App 的计数；`1259` 累加，`1297–1302` 只有总计数归零才清除当前会话 running。B 完成时仍被 A 的流计数影响。流文本缓冲同样是 App 级，需一起检查隔离。

**建议**：按 sessionId/runId 保存请求计数、运行状态和流缓冲；B 是否可输入仅由 B 的状态决定。

## R2-02 / P1：运行中刷新后不再同步后续结果

**复现**：session-005 发出“列出 80 项测试点”的纯文字请求，运行中整页刷新，保持该会话等待后台完成。

**实际**：后台 run `e3115c2c-b1b4-4777-9d23-a4214da5bdef` 已 `completed`（endedAt=1788603638983），页面仍显示“模型思考中 / 正在执行”，无最终回复，保留停止按钮。再次加载会话才能恢复。

**原因**：`web/src/App.tsx:439–454` 只获取会话快照；`457–472` 在初始加载/切换时调用。`1267` 的流属于原提交连接；刷新后没有重新订阅，也没有对仍运行的会话轮询状态。已有运行记录仅解决持久化，没有解决重新连接后的持续同步。

**建议**：增加可恢复的事件订阅或运行期间的有界轮询，终态时刷新消息；不能靠用户再次刷新。

## R2-03 / P1：PageCraft 文件未保存草稿刷新后无提示丢失

**复现**

1. session-004 打开 PageCraft → 文件 → README.md。
2. 仅在编辑器输入测试标记 `QA-UNSAVED-20260905`，不点保存。
3. 确认出现圆点、`保存 Ctrl+S` 和 `markdown · 未保存`。
4. 整页刷新，再回原会话重开 README.md。

**实际**：没有离开提醒；测试草稿消失，恢复磁盘原文，显示“已保存”。草稿未自动恢复，也没有可恢复入口。

**原因**：`plugins/dsh-frontend-feedback/src/client/source-workspace.tsx:272` 的 openFiles/draft 仅存在 React 状态中。`639–641` 的未保存确认只覆盖文件工作区的显式关闭，没有覆盖浏览器刷新/卸载，也未持久化草稿。

**建议**：统一未保存保护；按会话、工作目录和文件路径保存草稿及基准 hash，刷新后恢复并检查磁盘冲突；离开提醒作为补充。

**数据保护**：本次从未点击保存；只读 `git diff -- README.md .gitignore` 无差异，试验仓库文件未更改。

## R2-04 / P2：运行早期刷新，同一条用户请求显示两遍

**复现**：同 R2-02，在请求已保存、尚未产生首次流式输出的时间窗刷新。

**实际**：界面依次出现相同请求 → “正在执行” → 相同请求。后台只创建了一个对应 run，不是执行了两次。

**原因**：`src/server/sessionApi.ts:135` 开始运行时未立即关联已保存的用户消息，messageIds 主要在后续流事件或 finish 时更新。`web/src/sessionTimeline.ts:18` 在找不到 owned user 时额外合成 prompt，而 messages 里已经有这条请求。

**建议**：建立提交/用户消息/run 的稳定关联，读快照时保证一致性；不要仅凭暂时为空的 messageIds 决定复制用户请求。

## R2-05 / P2：整页刷新切到另一个会话

**复现**：当前选择 session-004，另一个会话 session-005 更新时间较新；整页刷新。

**实际**：页面自动选中 session-005，而不是正在查看的 session-004。PageCraft 草稿恢复测试中实际发生，需要手动切回。

**原因**：`web/src/App.tsx:430–436` 初始 selectedSessionId 为空时选取排序后的第一个会话，未恢复之前选择的会话。草稿虽已按会话持久化，当前会话选择本身没有持久化。

**建议**：使用 URL 或标签页存储恢复当前会话，只有已删除/失效时才回退。避免用户刷新后无意在不同项目会话发送需求。

## R2-06 / P3：目录加载失败后仍显示“正在读取文件夹”，导航入口失效

**复现**：在目录输入框打开 `D:\project\__QA_NONEXISTENT_20260905__`。

**实际**：显示原始 `ENOENT: no such file or directory, stat ...`，标题仍为“正在读取文件夹”；“盘符列表”和“选择当前文件夹”均禁用，不能直接导航回上个有效位置。

**恢复验证**：重新手输完整有效 Conduit 路径可以恢复，未发生永久锁死。

**原因**：`web/src/App.tsx:901` 加载前清空 directoryListing；`2084` 无 listing 时一律显示正在读取；`2100` 的盘符入口依赖已丢失的 listing。

**建议**：错误态与加载态分离，保留上个有效目录并提供始终可用的盘符/主目录入口；将系统错误转换为清楚的中文提示。

## R2-07 / P3：普通纯文本配置文件不能在 PageCraft 编辑

**复现**：PageCraft → 文件 → Conduit `.gitignore`。

**实际**：显示“此文件不作为文本打开”“是二进制或暂不支持编辑的文件”，没有文本编辑器；README.md 则可正常打开。

**原因**：`plugins/dsh-frontend-feedback/src/workspace.ts:92` 的文本类型采用扩展名白名单，`152` 只看扩展名，没有覆盖常见无扩展名/点文件。

**建议**：对 `.gitignore`、Dockerfile、LICENSE 等常见纯文本增加文件名规则，结合大小与二进制内容检测，而不是无扩展名一律不可编辑。秘密文件仍应有单独的显示/编辑策略。
