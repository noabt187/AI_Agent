# AI Agent 与 PageCraft 状态边界修复设计

日期：2026-09-06。基线：`623ff4a6bbb611a99d3087dc2ae8960dea097d49`（`lwm_dev`）。

状态：用户已确认总体方案及两项批注意见，A/B/C 实现已落地；最终源代码修复与验证按本设计执行。当前浏览器/同包验收边界见 `docs/testing/2026-09-06-round3-verification.md`，原生 Confirm/丢弃仍待验收。

## 1. 已确认的决策

采用“宿主任务状态边界调整 + 宿主退出交互局部修复 + 同包 PageCraft 编辑器修复”。保留 Cordis 插件宿主、现有运行队列、运行记录、工具服务和 PageCraft 安装方式。不移植整个 DSH 内核，不另造宿主专用 PageCraft 副本，不新增工作流框架、全局快捷键插件系统或数据库。

用户批注形成以下硬性要求：

- PageCraft 的退出与 Agent 对话终止完全分离。关闭插件、关闭文件工作区及相关退出确认，均不得调用 Agent abort 或取消运行。
- 最新请求是本轮执行依据；旧目标只是背景。停止保留历史、不回滚文件；明确继续可恢复原任务；替代任务不得沿用旧方案授权；确认绑定任务及方案版本；运行结束不等于任务完成。

第三轮测试已确认的问题及运行证据记录在 `docs/testing/2026-09-06-browser-round3.md`。本设计针对 R3-01 至 R3-04，不把代码推断中的潜在风险描述成额外复现的问题。

## 2. 根因与修改归属

| 问题 | 当前原因 | 修改归属 | 是否改变 PageCraft 宿主接口 |
| --- | --- | --- | --- |
| R3-01 旧任务覆盖新指令 | 会话级 goal、确认与权限混用；停止只中断计算，后续仍注入旧目标 | AI Agent 任务生命周期与请求上下文 | 否 |
| R3-02 Esc 退出误停 Agent | App 在 window 上无条件监听 Escape 并 abort | AI Agent 网页交互 | 否 |
| R3-03 丢弃后编辑区未重置 | React draft 更新，但 CodeMirror 没有同步外部 value 变化 | PageCraft 编辑器适配组件 | 否 |
| R3-04 CRLF 撤销后仍 dirty | 编辑器序列化为 LF，保存和 dirty 判断使用另一种表示 | PageCraft 文本格式处理 | 否 |

不采用“停止时清空所有状态”的补丁：它会破坏继续任务。不采用“每次输入就强制重建 CodeMirror”的补丁：它会损坏光标与撤销体验。不在宿主中查询 PageCraft 私有 DOM 后专门绕过：其他插件仍会重复遇到同类问题。

## 3. 实施单元 A：宿主任务生命周期

### 3.1 三类状态，各有唯一负责人

| 状态 | 内容 | 负责人 |
| --- | --- | --- |
| Session | 历史消息、目录、仓库配置、记忆设置 | 现有会话存储与服务 |
| Task | 当前目标、方案版本、进度、待确认项、写授权、暂停/结束状态 | 新的轻量任务状态模块，由 Orchestrator 调用 |
| Turn / Run | 本次实际输入、输入意图、运行 ID、用户消息 ID、任务版本、运行终态 | 请求协调逻辑与现有 RunStore |

任务模块采用纯状态转换加现有持久化，不增加后台调度器。Task 的阶段与 Run 的状态含义不同：任务可在某次运行结束后等待确认或处于暂停状态。运行的 queued/running/completed/failed/cancelled/interrupted 仍由 RunStore 管理，不另设一份可独立写入的 running 标志。

拟新增的内部记录：

- `TaskState`：`id`、`revision`、`objective`、`phase`、需求/方案快照、已有进度、待确认记录、授权记录、关联的最近运行 ID。
- `phase`：`active`、`awaiting_input`、`awaiting_confirmation`、`paused`、`completed`、`cancelled`。
- `PendingConfirmation`：唯一 `id`、`taskId`、`taskRevision`、确认种类、完整展示的方案快照、来源运行 ID。不得继续使用 `message || prompt` 丢失真正待确认的方案正文。
- `WriteApproval`：绑定 `taskId`、`taskRevision`、`confirmationId` 和工作目录/仓库目标快照。它替代会话级可独立修改的 `designConfirmed`。
- `TurnContext`：只读的本轮输入、`runId`、`userMessageId`、`taskId`、`taskRevision`、输入意图和工作目录快照。CLI 没有 HTTP run 时生成本轮标识，遵守相同转换规则。

现有工具执行接口中的布尔写开关可以保留为适配输出，但必须由当前任务授权计算，不能成为第二份权限状态。本轮只解决任务/方案版本级授权，不声称增加了逐文件、逐命令的权限系统。

### 3.2 输入意图与转换规则

不依赖新增 LLM 分类器决定是否继承写权限。网页明确操作携带意图；普通文本走确定性默认规则。

| 输入/事件 | 任务与权限行为 |
| --- | --- |
| 普通新请求 | 本轮严格以该输入为准。默认建立新任务，不继承旧授权；历史消息继续可见 |
| awaiting_input 时收到普通输入，或明确“修改方案”操作 | 按当前任务修订处理并增加 revision，保留必要背景/进度，旧待确认记录和写授权失效；新内容即使改变方向也优先于旧目标 |
| 明确继续（网页意图，或完整文本“继续”/“continue”） | 仅恢复当前可继续任务；不得选择另一任务或把普通新请求猜成继续 |
| 纯确认 | 只消费请求接收时绑定的待确认记录；执行时再核对 taskId、revision、confirmationId |
| “确认，但只修改某文件”等带约束文本 | 不是纯确认，按新请求或方案修订处理，不能通过包含“确认”二字开放写权限 |
| 停止按钮 / CLI 中断当前运行 | Run 终止，当前任务暂停；保留历史、已执行结果和进度，不回滚文件 |
| 明确取消任务（取消/cancel/不做了） | 任务 cancelled，清除待确认和有效授权，历史保留；之后不能用“继续”自动复活 |
| Agent ask_user / confirm | 保存为等待输入/等待确认，Run 可以正常结束，但 Task 不算完成 |
| Agent chat | 表示本轮回复结束，不推断长期任务完成；下一条普通输入仍按最新请求处理 |
| Agent done | 仅结束匹配本次 taskId/revision 的任务，同时关闭其授权 |

仅同时存在一个当前任务，不增加多任务调度面板。替换任务后，旧信息仍在会话历史及已有运行记录中，但不再作为自动执行目标。对不属于明确控制词的自然语言，默认执行最新输入，不能用猜测恢复旧授权；需要澄清时由 Agent 只读询问。

新建或修订时，objective 记录最新任务输入；先前目标、问题及方案单列为背景，不拼成另一条优先于用户的命令。确认/继续只引用其绑定版本的 objective。输入判定优先处理带标识的控制操作及明确取消/继续，再匹配有效待确认项；没有待确认项但处于 awaiting_input 时，“可以”等短回答属于用户补充，不误报为过期确认。仅既无待确认项也无待回答问题的孤立纯确认，返回无可确认方案提示。

停止期间任何工具都不得继续消费授权。明确继续同一任务时，只有任务版本、工作目录和方案均未改变，才可恢复先前已批准的同版本权限；若此前尚未批准，则恢复后重新展示待确认方案并生成新 confirmationId。新请求、更换目录、修改方案和显式取消均不满足恢复条件。

### 3.3 版本化确认及队列

保持现有普通 prompt 调用可用。AI Agent 自己的网页 stream 请求增加可选控制信息，以表达 confirm、revise、resume；不改变 PageCraft 的 `session.prompt(content, 'queue')` 和它依赖的 DSH 客户端服务。

- 网页确认按钮携带它实际展示的 confirmationId、taskId、taskRevision。候选方案选择随请求一并提交，必须属于该确认快照；不识别或过期的选择被拒绝。
- 无控制信息的旧客户端/CLI 输入纯“确认”时，在接收请求那一刻绑定当前待确认记录，不能等它排到队首才随意选择最新方案。
- 无待确认记录、也没有待回答问题时收到纯确认，应提示“当前没有可确认的方案”，不授权、不调用写工具。带过期标识的网页确认始终拒绝，不降级为普通回答。
- 排队后任务或方案已改变时，拒绝旧确认并要求重新查看，不自动转为确认新方案。
- 确认撤销接口也核对 confirmationId，旧页面不能撤销新页面产生的另一项确认。
- 保留同会话 FIFO 与不同会话隔离。停止只针对调用时捕获的活动运行，不顺带清空队列或取消后继请求；不得由延迟回调暂停另一项新任务。

### 3.4 上下文、工具执行和持久化

- 本轮输入只保留一份权威值；上下文中的旧方案明确标为历史/背景。普通新任务不注入旧 goal 为“用户目标”。
- 记忆检索以当前请求为主；确认/继续可以引用其绑定任务，不能因内存里的旧 goal 改为检索旧任务。
- 每次写工具执行前验证活动任务、版本、目录快照和有效授权，并检查中断信号。实际工具仍通过现有服务执行。
- stop、finish、error 的宿主状态收尾不使用已取消的执行 signal 阻止必要持久化。执行流程被中断与宿主记录中断结果是两件事。
- 状态写入串行、原子替换；锁仅保护短状态更新，不跨越模型请求或等待工具，避免停止路径死锁。
- Task 快照与 runs.json 不承诺跨文件数据库事务。通过共同 runId/taskId/revision 在加载时对账；不一致的运行按 interrupted/paused 处理，授权不自动恢复。
- 结果及异步回调只有在任务 ID、版本和运行归属匹配时才能修改当前 Task。已终止 Run 继续沿用现有终态保护。
- 工作目录/仓库执行目标在运行中不允许切换；空闲时变更使旧确认和授权失效。已排队请求的目录快照不匹配时给出明确错误，不悄悄在新目录执行。

界面将普通 `RunStatus.completed` 展示为“本轮运行结束”，等待确认、暂停等状态分别展示。只有匹配的任务完成结果才显示“任务完成”。这是状态语义修正，不是保证模型答案必然正确的自动评测器。

### 3.5 旧会话迁移

为 Orchestrator 状态增加 schemaVersion。旧 messages/runs 不清空、不改写原文；旧 goal、需求和进度按暂停的旧任务背景迁入。没有 taskId/revision 的旧 designConfirmed 不迁为有效授权，旧待确认内容仅保留为需重新展示的方案。

迁移采用加载时归一化，首次落盘前保留一次旧快照，并原子写入新格式。只操作当前实际加载的会话，不批量扫描改写所有历史目录。未知版本、损坏的任务快照应显式报错并禁用写执行，不能静默重置成可写的新会话。

## 4. 实施单元 B：网页退出与 Agent 停止分离

当前聊天输入框在运行时被禁用，把 Esc 简单移动到该 textarea 无法提供有效停止快捷键。因此本轮采取最直接、可验证的规则：移除网页全局 Esc 停止，网页使用明确的停止按钮，不新增替代快捷键。

- PageCraft 的 Esc、关闭按钮、文件工作区退出确认只影响 PageCraft。确认离开或取消离开，两条分支都不能发送 Agent abort。
- 宿主输入法、会话重命名、目录弹窗等局部 Esc 同样不能终止任务。
- 保留 PageCraft 现有自身退出处理，不为修复宿主误停止而改动插件接口或插入宿主专用 DOM 判断。
- 停止按钮、状态恢复和运行归属保护沿用现有能力，并接受实施单元 A 的生命周期规则。
- CLI 没有网页弹层，现有终端 Esc 中断可以保留；它与网页 Esc 是不同输入来源，但都必须采用统一的任务暂停/收尾规则。

验收不仅检查弹窗消失，还检查 Agent 运行记录没有变为 cancelled，并确认请求最终能正常结束。

## 5. 实施单元 C：PageCraft 文档与编辑器一致性

### 5.1 内容的单一依据与编辑器适配

保留现有文件工作区状态及 IndexedDB 草稿服务；抽出独立 CodeEditor 适配组件和小型文本格式模块，不新建全局编辑状态库。

文档状态持有磁盘基准、当前草稿和格式信息；CodeMirror 管理编辑视图、光标、选择及撤销。适配层将用户编辑回传给文档状态，并显式接收外部内容更新，不允许两份内容各自独立变化。

- 文档身份包括 sessionId、rootPath、selectedFolder、文件路径，不能只用文件名判断归属。
- 每次用户变更增加 editRevision；丢弃、接受磁盘版本、历史恢复等内容替换增加 resetRevision。异步操作带上文档身份和版本，不能只靠字符串相等判断有没有新编辑。
- 普通输入不重建 EditorView，不因父组件重新渲染丢光标/滚动位置/撤销记录。
- 外部重置显式同步全文，禁止当作用户输入再回写草稿，避免循环。
- 丢弃成功后同步磁盘原文并清空旧撤销/重做历史，不能用 Ctrl+Z 复活被丢弃的内容。
- 保存成功且无后续编辑时更新磁盘基准、dirty 与缓存；若有新编辑，保留新文本及其撤销状态，不能用较旧的保存结果替换编辑区。
- 接受外部文件版本、历史恢复、冲突处理使用相同内容重置入口。正常定位行号不算内容重置，不应清空撤销历史。

### 5.2 草稿、保存和失败

维持现有按文档串行缓存操作、revision 条件清理、容量和敏感文件保护，不能为解决显示问题降低这些保障。

- 丢弃先确认、完成对应缓存操作，再重置当前文档。操作期间若有新版本出现，保留新版本并提示，不给出“全部已丢弃”的成功状态。
- 缓存丢弃失败时保留编辑器、dirty 和草稿，明确失败。
- 磁盘保存成功但缓存清理失败时，分别说明磁盘成功与缓存失败；后续编辑仍 dirty。
- 缓存恢复/冲突弹窗中的内容、编辑区及最终保存内容必须来自同一份文档快照。

### 5.3 换行与 UTF-8 格式

对纯 LF、纯 CRLF 和纯 CR 文本提供保真往返。文档内部采用统一行表示，格式元数据记录换行类型和 UTF-8 BOM；dirty 判断、缓存和磁盘保存统一经过同一序列化入口。不得再将默认 `doc.toString()` 的 LF 结果直接当作磁盘原文。

- UTF-8 解码必须保留 BOM 信息；文件内容、字节数、hash 和保存返回快照使用一致的实际 UTF-8 字节语义。严格 UTF-8 校验及二进制拦截继续保留。
- 普通编辑后撤销到基准内容，应同时恢复原换行/BOM 和 clean 状态。
- 无换行文件默认新增 LF；若已有磁盘基准格式则沿用该格式。保留末尾是否存在换行这一事实，不自动补齐。
- 混合换行文件本轮只读展示，明确提示“不自动统一混合换行”；不加入新的格式转换 UI，也不允许普通保存悄悄重写整份文件。
- 旧 IndexedDB 草稿键和内容保留；新增格式元数据可选。旧记录格式缺失且 baseHash 一致时按基准文件格式恢复，不丢文本。baseHash 不一致仍进入冲突流程，不伪造匹配或静默丢弃。
- BOM 保留会使部分旧缓存的历史 hash 不再匹配，应按冲突处理；不得通过忽略 BOM 的 hash 绕过真实文件版本检查。

### 5.4 同包兼容边界

修改位于 `plugins/dsh-frontend-feedback` 的同一源包，重建同一套 lib 产物。保持现有 npm 包名、Cordis patch、客户端注入项、公开导出和文件接口字段兼容；不增加 AI Agent 特有的必需宿主服务。

普通 prompt 仍走原 DSH 兼容会话接口；TaskState 与版本化确认是 AI Agent 内部能力，不要求 DSH 或 PageCraft 实现。格式元数据属于插件内部文档/缓存，不把整套编辑器状态传给宿主。

## 7. 验收要求

### 7.1 宿主状态

- 重放 R3：取消 A → 发送读文件的 B；模型实际请求中的本轮依据是 B，没有旧 A 冒充当前目标；B 的工具调用和输出归属正确。
- 新建会话发送同一 B 作为对照；确定性测试使用可控模型响应，浏览器再跑真实模型，不把某次模型成功当作全部生命周期正确。
- 暂停 → 刷新/重启 → 明确继续；保留历史和进度，只有同任务同版本同目录的既有授权可恢复。
- 新任务、方案修订、目录改变后旧确认无效；多标签旧确认、队列延迟确认、重复确认、带约束的确认均不扩大权限。
- 停止发生在模型返回前、工具进行中、结果完成边界时，最终记录正确，没有回调污染后继任务。
- waiting/paused/chat/done 区分正确；旧格式迁移保留历史、拒绝继承无版本写授权；损坏状态失败可见。

### 7.2 退出隔离

- Agent 运行时，PageCraft 预览地址、编辑器、退出确认的 Esc/关闭操作均不 abort Agent。
- 分别确认和取消未保存退出；背景任务在两条分支中均继续。
- 点击停止按钮仍能停止正确运行；CLI 中断仍暂停任务；插件 UI 不依赖 Agent 的停止状态才能关闭。

### 7.3 文档保真

- 丢弃后同时断言编辑器实际文本、dirty、保存按钮、IndexedDB；重新输入和撤销不能复活已丢弃内容。
- 丢弃期间编辑、保存期间编辑、缓存失败、文件冲突、刷新恢复、接受磁盘版本均覆盖，保留此前竞争保护。
- LF/CRLF/CR、BOM、空文件、无末尾换行、多次输入撤销、中文与非 BMP 字符验证文本及字节往返；混合换行只读且未改写磁盘。
- 编辑器组件测试必须在 DOM 环境挂载真实组件。现有仅检查 bundle 启动按钮的服务端渲染测试不能替代它。

### 7.4 交付检查与保护

最终运行宿主测试/构建、web 构建、插件 check 和同包安装集成。以打包后的同一产物在 AI Agent 和本地 DSH 的隔离测试配置中验证文件编辑、草稿丢弃和退出隔离；记录包版本/产物 hash。DSH 环境无法启动时明确列为未验收，不宣称双宿主通过。
